## Acceptance checklist

### P0

- [ ] Unauthenticated attendance, profile reset, and private-photo requests are rejected.
- [ ] Cross-employee and cross-company requests cannot replay events or access images.
- [ ] Repeated attendance event IDs cannot create duplicate logs; clock-in and clock-out events are distinct.
- [ ] A lost enrollment response retried after baseline reset cannot return stale enrollment success.
- [ ] Reset + enrollment stores a readable private baseline; a later punch compares against that baseline.
- [ ] Failed blink, provider error, malformed provider response, or capture mismatch creates neither an attendance log nor an enrolled baseline.
- [ ] An ordinary valid-baseline punch does not replace the baseline.
- [ ] Face++ secrets and biometric content never appear in logs or client diagnostics.
- [ ] Production private storage persistence, access policy, retention, backups, and restoration are verified.
- [ ] Effective local/test DB targets are positively identified before database operations.

### P1/P2

- [ ] Authentication, employer/employee lifecycle, leave, attendance, and reporting workflows pass positive, negative, authorization, and failure-path tests.
- [ ] Payroll behavior is reviewed against approved business/statutory rules.
- [ ] Android development build completes and camera/ML Kit/liveness behavior is verified on a physical supported device.
- [ ] Offline queue remains fail-closed unless selfie and liveness evidence can be securely persisted and replayed.
- [ ] Release variables, HTTPS, monitoring, rollback, backup, restore, and image retention are documented and verified.
